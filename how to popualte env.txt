This guide provides the definitive steps to recreate or gather every credential in your `.env.local` file, following the secure "Least Privilege" model we established.

---

### 1. Auth & Session Security
These are generated by you to lock down the dashboard itself.

*   **`AUTH_SECRET`**: Open a terminal and run: `openssl rand -base64 32`. Paste the result.
*   **`TWO_FACTOR_SECRET`**: This is a 32-character base32 string. You can use any random string generator or a site like [bitwarden.com/password-generator](https://bitwarden.com/password-generator/) (set to "Passphrase").
*   **`DASHBOARD_PASSWORD`**: Choose a strong password. This is the only thing a user needs to type to enter your console.

---

### 2. Cloudflare (Telemetry & DNS)
You need two different tokens. One for the **Dashboard File** (Telemetry) and one for **Nginx Proxy Manager** (SSL Certs).

**A. For the `.env.local` (Telemetry):**
1.  **`CLOUDFLARE_ZONE_ID`**: Select your domain in Cloudflare. Scroll down on the "Overview" page. Copy the **Zone ID** from the sidebar.
2.  **`CLOUDFLARE_API_TOKEN`**: Go to **My Profile > API Tokens > Create Token**.
    *   Use the **Read analytics and logs** template.
    *   **Permission**: `Zone > Analytics > Read`.
    *   **Resources**: `Include > Specific Zone > grtlabs.xyz`.

**B. For Nginx Proxy Manager (SSL DNS Challenge):**
1.  Create another token: **My Profile > API Tokens > Create Token**.
    *   Use the **Edit zone DNS** template.
    *   **Permission**: `Zone > DNS > Edit`.
    *   **Resources**: `Include > Specific Zone > grtlabs.xyz`.
    *   *Use this token inside NPM's SSL "DNS Challenge" box.*

---

### 3. Proxmox VE (`pve.grtlabs.xyz`)
We use "Privilege Separation" to ensure the dashboard cannot delete VMs.

1.  **Create Role**: Go to **Datacenter > Permissions > Roles**. Create a role named `dashboard` with these privileges: `VM.Audit`, `Datacenter.Audit`, `Sys.Audit`.
2.  **Create Token**: Go to **Datacenter > Permissions > API Tokens**.
    *   User: `root@pam`. Token ID: `grtlabs`.
    *   **Uncheck** "Privilege Separation" (or check it and manually add the role in the next step).
3.  **Assign Permission**: Go to **Datacenter > Permissions > Add > API Token Permission**.
    *   Path: `/`
    *   Token: `root@pam!grtlabs`
    *   Role: `dashboard`
4.  **Result**: Copy the **Secret** into `PROXMOX_TOKEN_SECRET`.

---

### 4. TrueNAS SCALE (`nas.grtlabs.xyz`)
1.  **Create User**: Go to **Credentials > Local Users**. Create `grtlabs_api`.
2.  **Grant Role**: Under **Privileges/Roles**, select **Readonly Admin**.
3.  **Enable Access**: Ensure **TrueNAS WebUI Access** is checked.
4.  **Generate Key**: Click on the user, scroll to **API Keys > Add**.
    *   Name: `grtlabs_dash`.
5.  **Result**: Copy the key into `TRUENAS_API_KEY`.

---

### 5. Home Assistant (`home.grtlabs.xyz`)
1.  Log in to Home Assistant.
2.  Click your **Profile Name** (bottom left).
3.  Click the **Security** tab at the top.
4.  Scroll to the very bottom: **Long-Lived Access Tokens**.
5.  Click **Create Token**. Name it `Grtlabs`.
6.  **Result**: Copy the long JWT string into `HOMEASSISTANT_TOKEN`.

---

### 6. Jellyfin (`media.grtlabs.xyz`)
1.  Log in to Jellyfin.
2.  Go to **Dashboard > Advanced > API Keys**.
3.  Click the **+** (Plus) button.
4.  Name it `Grtlabs`.
5.  **Result**: Copy the key into `JELLYFIN_API_KEY`.

---

### 7. Networking & SSL (The "Glue")
To make the domains in your file work, you must complete these two outside steps:

1.  **Cloudflare DNS**:
    *   Create **CNAME** records for `pve`, `nas`, `home`, and `media`.
    *   Point them all to your "Master" domain (the one updated by your Dynamic DNS script).
    *   Ensure **Proxy Status** is **Proxied** (Orange Cloud).
2.  **Nginx Proxy Manager**:
    *   Add each host (e.g., `pve.grtlabs.xyz`).
    *   Forward to the internal IP (e.g., `192.168.1.17`) and port (`8006`).
    *   Request an SSL cert using the **DNS Challenge** (with the Cloudflare DNS token).
    *   **Advanced Tab fix**: For Proxmox and TrueNAS, paste `proxy_ssl_verify off;` into the Advanced box.

### Final Step
Once the file is saved, **restart your Next.js environment**. 
*   If testing locally: `npm run dev`
*   If deployed: Restart the container/service.

**Everything is now secure, verified via SSL, and dynamic-IP proof.**
